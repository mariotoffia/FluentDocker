# Reference: Building a thin `IModelApiConnection` / `ModelApiConnection`

This digest is an exhaustive, copy-from reference distilled from the Docker API connection layer. The goal is a NEW thin HTTP connection that mirrors the transport mechanics (unix socket / npipe / TCP / TLS, streaming, ping, IAsyncDisposable) but **drops the Docker-specific `/_ping` API-version negotiation and `/v{version}` path prefixing**. All file:line refs are to the Docker originals you are modeling on.

## (1) HttpClient construction: TCP vs Unix socket vs npipe — EXACT ConnectCallback code

### Top-level dispatch (`DockerApiConnection.cs:196-210`)
A static factory returns `(SocketsHttpHandler handler, string baseAddress)` based on URI scheme. **The base address is always a synthetic `http://localhost` for socket/pipe transports** (the host part is irrelevant once `ConnectCallback` hijacks the connection):

```csharp
private static (SocketsHttpHandler handler, string baseAddress) CreateHandler(
    string host, DockerApiConnectionConfig config)
{
  var uri = new Uri(host);
  return uri.Scheme.ToLowerInvariant() switch
  {
    "unix"  => CreateUnixSocketHandler(uri, config),
    "npipe" => CreateNamedPipeHandler(uri, config),
    "tcp" or "http" => CreateTcpHandler(uri, config, useTls: false),
    "https" => CreateTcpHandler(uri, config, useTls: true),
    _ => throw new ArgumentException($"Unsupported URI scheme: {uri.Scheme}. " +
        "Use unix://, npipe://, tcp://, or https://", nameof(host))
  };
}
```

### Constructor wiring (`DockerApiConnection.cs:38-57`)
```csharp

{
  ArgumentNullException.ThrowIfNull(config);
  _config = config;

  var host = config.Host ?? GetDefaultHost();

  {
    BaseAddress = new Uri(baseAddress),

```
Key: `new HttpClient(handler, disposeHandler: true)` so disposing the client disposes the handler. `Timeout = config.RequestTimeout`. `BaseAddress` lets every call pass only a path.

### UNIX DOMAIN SOCKET — EXACT ConnectCallback (`DockerApiConnection.cs:212-230`)
```csharp
private static (SocketsHttpHandler, string) CreateUnixSocketHandler(
    Uri uri, DockerApiConnectionConfig config)
{
  var socketPath = uri.AbsolutePath;
  var handler = new SocketsHttpHandler
  {
    ConnectCallback = async (context, ct) =>
    {
      var socket = new Socket(
                  AddressFamily.Unix, SocketType.Stream, ProtocolType.Unspecified);
      var endpoint = new UnixDomainSocketEndPoint(socketPath);
      await socket.ConnectAsync(endpoint, ct).ConfigureAwait(false);
      return new NetworkStream(socket, ownsSocket: true);
    },
    ConnectTimeout = config.ConnectionTimeout
  };
  return (handler, "http://localhost");
}
```
Notes: `socketPath` comes from `uri.AbsolutePath` (e.g. `unix:///var/run/docker.sock` -> `/var/run/docker.sock`). `NetworkStream(socket, ownsSocket: true)` makes the stream dispose the socket. Returns synthetic `http://localhost` base.

### NAMED PIPE (Windows) — EXACT ConnectCallback (`DockerApiConnection.cs:232-249`)
```csharp
private static (SocketsHttpHandler, string) CreateNamedPipeHandler(
    Uri uri, DockerApiConnectionConfig config)
{
  var pipeName = uri.AbsolutePath.TrimStart('/');
  var handler = new SocketsHttpHandler
  {
    ConnectCallback = async (_, ct) =>
    {
      var pipe = new NamedPipeClientStream(
                  ".", pipeName, PipeDirection.InOut, PipeOptions.Asynchronous);
      await pipe.ConnectAsync((int)config.ConnectionTimeout.TotalMilliseconds, ct).ConfigureAwait(false);
      return pipe;
    },
    ConnectTimeout = config.ConnectionTimeout
  };
  return (handler, "http://localhost");
}
```
Notes: `pipeName` = `uri.AbsolutePath.TrimStart('/')` (e.g. `npipe:////./pipe/docker_engine` -> `./pipe/docker_engine` after trim... actually `//./pipe/docker_engine`). Server `"."` = local machine. `NamedPipeClientStream` is itself a Stream, returned directly.

### TCP / HTTP / HTTPS — handler + base address (`DockerApiConnection.cs:251-320`)
TCP has **no ConnectCallback** — it relies on the default DNS/socket connect, only configuring `ConnectTimeout` and (optionally) `SslOptions`:
```csharp
private static (SocketsHttpHandler, string) CreateTcpHandler(
    Uri uri, DockerApiConnectionConfig config, bool useTls)
{
  var handler = new SocketsHttpHandler { ConnectTimeout = config.ConnectionTimeout };
  var hasCerts = !string.IsNullOrEmpty(config.CertificatePath);
  if (useTls || hasCerts) { /* TLS — see section (2) */ handler.SslOptions = sslOptions; }

  var scheme  = (useTls || hasCerts) ? "https" : "http";
  var port    = uri.Port > 0 ? uri.Port : (useTls ? 2376 : 2375);   // Docker default ports
  var baseAddress = $"{scheme}://{uri.Host}:{port}";
  return (handler, baseAddress);
}
```
**For a non-Docker thin connection: change the default ports 2376/2375 to whatever your service uses (or require an explicit port).** The "promote to https if certs present even when scheme was tcp" behavior (`hasCerts` forces https) is a Docker convenience — keep or drop as you wish.

### Default host (`DockerApiConnection.cs:189-194`) — Docker-specific, REPLACE
```csharp

        ? "npipe:////./pipe/docker_engine"
```

## (2) HTTPS / TLS configuration — EXACT code (`DockerApiConnection.cs:259-313`)
Inside `CreateTcpHandler`, guarded by `if (useTls || hasCerts)`:
```csharp
var sslOptions = new SslClientAuthenticationOptions();

if (hasCerts)
{
  var certPath = Path.Combine(config.CertificatePath, "cert.pem");
  var keyPath  = Path.Combine(config.CertificatePath, "key.pem");

  if (File.Exists(certPath) && File.Exists(keyPath))
  {
    var clientCert = X509Certificate2.CreateFromPemFile(certPath, keyPath);
    sslOptions.ClientCertificates = [clientCert];          // mutual TLS client cert
  }

  if (!config.VerifyTls)
  {
#pragma warning disable CA5359 // Intentional: user opted out via VerifyTls=false
    sslOptions.RemoteCertificateValidationCallback = (_, _, _, _) => true;
#pragma warning restore CA5359
  }
  else
  {
    var caPath = Path.Combine(config.CertificatePath, "ca.pem");
    if (File.Exists(caPath))
    {
#if NET9_0_OR_GREATER
      var caCert = X509CertificateLoader.LoadCertificateFromFile(caPath);
#else
      var caCert = X509Certificate2.CreateFromPemFile(caPath);
#endif
      sslOptions.RemoteCertificateValidationCallback = (_, cert, chain, errors) =>
      {
        if (errors == SslPolicyErrors.None) return true;
        if (chain == null || cert == null) return false;
        chain.ChainPolicy.TrustMode = X509ChainTrustMode.CustomRootTrust;
        chain.ChainPolicy.CustomTrustStore.Add(caCert);
        return chain.Build(new X509Certificate2(cert));
      };
    }
  }
}
else if (!config.VerifyTls)
{
#pragma warning disable CA5359
  sslOptions.RemoteCertificateValidationCallback = (_, _, _, _) => true;
#pragma warning restore CA5359
}

handler.SslOptions = sslOptions;
```
TLS rules summary:
- Cert dir convention: `cert.pem` + `key.pem` (client cert), `ca.pem` (custom root). Built via `Path.Combine(config.CertificatePath, ...)`.
- Client cert loaded with `X509Certificate2.CreateFromPemFile(certPath, keyPath)`, assigned to `sslOptions.ClientCertificates = [clientCert]` (collection-expression syntax).
- `VerifyTls == false` -> accept any server cert via `RemoteCertificateValidationCallback => true` (suppress CA5359).
- `VerifyTls == true` + `ca.pem` present -> custom root trust: `X509ChainTrustMode.CustomRootTrust`, add CA to `CustomTrustStore`, `chain.Build(...)`. Note the net9+ `#if` switching from obsolete `CreateFromPemFile` to `X509CertificateLoader.LoadCertificateFromFile`. (Project targets net10, so the `NET9_0_OR_GREATER` branch is the live one.)
- Without certs and `VerifyTls==true`, default system validation applies (no callback set).

This TLS block is transport-only and **fully reusable as-is** for the thin connection — nothing Docker-specific here.

### Non-streaming verbs (`DockerApiConnection.cs:66-90`)
In Docker these all funnel through `GetVersionedPathAsync(path)` to prepend `/v{version}`. **For the thin connection, delete `GetVersionedPathAsync` entirely and pass `path` straight through.** Thin equivalents:
```csharp
public Task<HttpResponseMessage> GetAsync(string path, CancellationToken ct = default)
    => _httpClient.GetAsync(path, ct);
public Task<HttpResponseMessage> PostAsync(string path, HttpContent content = null, CancellationToken ct = default)
    => _httpClient.PostAsync(path, content, ct);
public Task<HttpResponseMessage> PutAsync(string path, HttpContent content, CancellationToken ct = default)
    => _httpClient.PutAsync(path, content, ct);
public Task<HttpResponseMessage> DeleteAsync(string path, CancellationToken ct = default)
    => _httpClient.DeleteAsync(path, ct);
```
(Docker versions are `async`/`await` only because of the version-lookup await; without it they can be pass-through. If you keep them `async`, use `.ConfigureAwait(false)`.)

### Streaming GET — `HttpCompletionOption.ResponseHeadersRead` + `ResponseOwningStream` (`DockerApiConnection.cs:92-100`)
```csharp
public async Task<Stream> GetStreamAsync(string path, CancellationToken ct = default)
{
  var response = await _httpClient.GetAsync(
      path, HttpCompletionOption.ResponseHeadersRead, ct).ConfigureAwait(false);
  response.EnsureSuccessStatusCode();
  var stream = await response.Content.ReadAsStreamAsync(ct).ConfigureAwait(false);
  return new ResponseOwningStream(stream, response);   // ties response lifetime to stream
}
```

### Streaming POST — build `HttpRequestMessage` to attach content + `ResponseHeadersRead` (`DockerApiConnection.cs:102-112`)
```csharp
public async Task<Stream> PostStreamAsync(string path, HttpContent content = null, CancellationToken ct = default)
{
  var request = new HttpRequestMessage(HttpMethod.Post, path) { Content = content };
  var response = await _httpClient.SendAsync(
      request, HttpCompletionOption.ResponseHeadersRead, ct).ConfigureAwait(false);
  response.EnsureSuccessStatusCode();
  var stream = await response.Content.ReadAsStreamAsync(ct).ConfigureAwait(false);
  return new ResponseOwningStream(stream, response);
}
```
**Critical idiom:** `HttpCompletionOption.ResponseHeadersRead` returns as soon as headers arrive so the body streams lazily (no buffering of the whole body). The non-streaming verbs use the default `ResponseContentRead` (fully buffered). The returned `Stream` MUST be a `ResponseOwningStream` so disposing the stream disposes the `HttpResponseMessage` (preventing connection/handler leaks).

### Higher-level JSON helpers (driver base, `DockerApiDriverBase.cs`) — pattern to copy in your model driver base
- `PostJsonAsync` body building: `new StringContent(JsonHelper.Serialize(body), Encoding.UTF8, "application/json")` when body != null else null (`:84-102`, `:149-166`).
- Source-gen variant: `JsonContent.Create(body, bodyTypeInfo)` (`:108-128`) — needs `System.Net.Http.Json`.
- `PutStreamAsync` sets content type: `new StreamContent(stream)` + `content.Headers.ContentType = new MediaTypeHeaderValue(contentType)` (`:182-198`).
- Response handling reads body string then deserializes for success, or extracts an error message on failure (`HandleResponseAsync<T>` `:380-397`). Stream-based source-gen variant deserializes directly off `response.Content.ReadAsStreamAsync` and guards `ContentLength == 0` for empty bodies (`HandleResponseFromStreamAsync` `:404-422`).
- Every helper wraps in `try { } catch (Exception ex) when (IsConnectionError(ex)) { return ...Failure(503, ...) }` — converts transport failures into a 503 ServiceUnavailable result instead of throwing.

### `ResponseOwningStream` — full pattern (`ResponseOwningStream.cs:14-90`)
A `sealed` `Stream` subclass using a primary constructor that owns BOTH the inner stream and the `HttpResponseMessage`:
```csharp
public sealed class ResponseOwningStream(Stream inner, HttpResponseMessage response) : Stream
{
  private readonly Stream _inner = inner ?? throw new ArgumentNullException(nameof(inner));
  private readonly HttpResponseMessage _response = response ?? throw new ArgumentNullException(nameof(response));
  private int _disposed;

  public override bool CanRead => !IsDisposed && _inner.CanRead;
  public override bool CanSeek => !IsDisposed && _inner.CanSeek;
  public override bool CanWrite => false;            // read-only response stream
  public override long Length => _inner.Length;
  public override long Position { get => _inner.Position; set => _inner.Position = value; }

  private bool IsDisposed => Volatile.Read(ref _disposed) != 0;
  private void ThrowIfDisposed() => ObjectDisposedException.ThrowIf(IsDisposed, this);

  public override int Read(byte[] buffer, int offset, int count) { ThrowIfDisposed(); return _inner.Read(buffer, offset, count); }
  public override async ValueTask<int> ReadAsync(Memory<byte> buffer, CancellationToken ct = default)
  { ThrowIfDisposed(); return await _inner.ReadAsync(buffer, ct).ConfigureAwait(false); }
  public override long Seek(long offset, SeekOrigin origin) { ThrowIfDisposed(); return _inner.Seek(offset, origin); }
  public override void SetLength(long value) => throw new NotSupportedException();
  public override void Write(byte[] buffer, int offset, int count) => throw new NotSupportedException();
  public override void Flush() => _inner.Flush();

  protected override void Dispose(bool disposing)
  {
    if (Interlocked.CompareExchange(ref _disposed, 1, 0) != 0) return;   // idempotent, thread-safe
    if (disposing) { _inner.Dispose(); _response.Dispose(); }
    base.Dispose(disposing);
  }

  public override async ValueTask DisposeAsync()
  {
    if (Interlocked.CompareExchange(ref _disposed, 1, 0) != 0) return;
    await _inner.DisposeAsync().ConfigureAwait(false);
    _response.Dispose();
    await base.DisposeAsync().ConfigureAwait(false);
  }
}
```
**This file is transport-agnostic — copy verbatim (rename namespace only).** Key idioms: `Interlocked.CompareExchange(ref _disposed, 1, 0) != 0` guard makes both sync and async dispose idempotent and race-safe; `Volatile.Read` for the `IsDisposed` check; write operations throw `NotSupportedException`; `ObjectDisposedException.ThrowIf(...)` guards reads.

## (6) Reading response streams without buffering

### A. `ReadLineAsync` / NDJSON via `StreamReader` (`DockerApiDriverBase.cs:240-324`)
The simple line-streaming pattern used for NDJSON progress streams. Note `[EnumeratorCancellation]` on the CT param, `yield break` on cancel/error, `await using` the stream, and `StreamReader` with `leaveOpen: true` (the outer `await using` owns disposal):
```csharp
protected async IAsyncEnumerable<string> ReadNdjsonStreamAsync(
    string path, [EnumeratorCancellation] CancellationToken ct)
{
  Stream stream;
  try { stream = await Connection.GetStreamAsync(path, ct).ConfigureAwait(false); }
  catch (Exception ex) { Logger.LogError(ex, "NDJSON stream open failed"); yield break; }

  await using var _ = stream.ConfigureAwait(false);
  using var reader = new StreamReader(stream, Encoding.UTF8,
      detectEncodingFromByteOrderMarks: false, bufferSize: 1024, leaveOpen: true);
  while (!ct.IsCancellationRequested)
  {
    string line;
    try { line = await reader.ReadLineAsync(ct).ConfigureAwait(false); }
    catch (OperationCanceledException) { yield break; }
    catch (Exception ex) { Logger.LogDebug(ex, "NDJSON stream read failed"); yield break; }

    if (line == null) break;                        // EOF
    if (string.IsNullOrWhiteSpace(line)) continue;  // skip blank lines
    yield return line;
  }
}
```
The POST variant (`:284-324`) is identical except it opens via `Connection.PostStreamAsync(path, content, ct)`. **Idiom rules:** you cannot `yield return` from inside a `try/catch`, so the read is wrapped in try/catch that sets the line, then the `yield` happens after; `[EnumeratorCancellation]` flows the `await foreach`'s token into `ct`.

### B. Allocation-free NDJSON via `PipeReader` + source-gen (`DockerApiDriverBase.Stream.cs:27-100`)
For high-throughput, deserialize each `\n`-delimited line straight from UTF-8 bytes with zero string-per-line allocation:
```csharp
protected static async IAsyncEnumerable<T> ReadNdjsonLinesAsync<T>(
    Stream stream, JsonTypeInfo<T> typeInfo,
    [EnumeratorCancellation] CancellationToken ct) where T : class
{
  var reader = PipeReader.Create(stream);
  try
  {
    while (true)
    {
      ReadResult result;
      try { result = await reader.ReadAsync(ct).ConfigureAwait(false); }
      catch (OperationCanceledException) { break; } // threw -> no result to AdvanceTo

      var buffer = result.Buffer;
      var keepGoing = true;
      while (keepGoing && TryReadLine(ref buffer, out var lineSeq))
      {
        var item = TryDeserializeLine(lineSeq, typeInfo);
        if (item != null) yield return item;
        if (ct.IsCancellationRequested) keepGoing = false;
      }
      reader.AdvanceTo(buffer.Start, buffer.End);   // MUST call after every ReadAsync
      if (!keepGoing || result.IsCompleted)
      {
        if (result.IsCompleted && buffer.Length > 0)
        {
          var item = TryDeserializeLine(buffer, typeInfo);
          if (item != null) yield return item;       // trailing line w/o newline
        }
        break;
      }
    }
  }
  finally { await reader.CompleteAsync().ConfigureAwait(false); }
}
```
Helpers (`:87-147`): `TryReadLine` uses `buffer.PositionOf((byte)'\n')`, slices the line, advances `buffer = buffer.Slice(buffer.GetPosition(1, position.Value))`. `TryDeserializeLine` trims a trailing `\r` (CRLF support), skips empty/whitespace-only (`IsWhitespaceOnly`), then `new Utf8JsonReader(lineBytes); JsonSerializer.Deserialize(ref utf8Reader, typeInfo)` inside `try/catch(JsonException)->null`. **Contract gotcha: `reader.AdvanceTo(buffer.Start, buffer.End)` must run after every successful `ReadAsync`; on a thrown `OperationCanceledException` you must NOT call AdvanceTo (hence the `break`).**

### C. Multiplexed binary framing (Docker stdout/stderr) — `StripDockerStreamHeaders` (`DockerApiDriverBase.Stream.cs:159-217`) — DOCKER-SPECIFIC
Docker's attach/logs multiplexed protocol = repeated 8-byte header `[1B streamType][3B zero padding][4B big-endian payloadSize][payload]`. Two-pass Span impl: first pass sums payload sizes, then `stackalloc byte[totalPayload]` if `<= 1024` else heap array, second pass copies payloads, returns `Encoding.UTF8.GetString`. Frame-size decode: `(b[o+4]<<24)|(b[o+5]<<16)|(b[o+6]<<8)|b[o+7]`. Header validity check: `bytes[0] <= 2 && bytes[1..3]==0`. **This is Docker-proprietary; a generic model HTTP service almost certainly does NOT use it — omit unless your target speaks the same hijacked-stream framing.** Companion `ReadExactAsync(Stream, byte[], count, ct)` (`:223-236`) handles partial reads (loop until `count` bytes or `read==0`), useful for any fixed-length binary framing you DO have.
