## (1) IDriverScopedBuilder members — Kernel + DriverId exposure

File: `/Users/mariotoffia/progs/github/FluentDocker/FluentDocker/Builders/IDriverScopedBuilder.cs:10-21`

```csharp

{
  public interface IDriverScopedBuilder
  {
    FluentDockerKernel Kernel { get; }   // line 15
    string DriverId { get; }             // line 20
  }
}
```

**Idiom for implementing it on a builder (copy verbatim):** every internal builder implements `IDriverScopedBuilder` *explicitly* (the props are not part of the public builder interface). Constructor takes `(FluentDockerKernel kernel, string driverId)` as a primary constructor. Pattern (from `ContainerBuilder.cs:21-32`, identical in `NetworkBuilder` InternalBuilders.cs:16-25, `VolumeBuilder` :101-110, `ComposeBuilder` :149-158, `PodBuilder.cs:15-21`):

```csharp
internal sealed partial class ContainerBuilder(FluentDockerKernel kernel, string driverId)
    : IContainerBuilder, IDriverScopedBuilder
{
  private readonly FluentDockerKernel _kernel = kernel;
  private readonly string _driverId = driverId;

  /// <inheritdoc />
  FluentDockerKernel IDriverScopedBuilder.Kernel => _kernel;
  /// <inheritdoc />
  string IDriverScopedBuilder.DriverId => _driverId;
  ...
}
```

So a new `ModelRunnerBuilder`/`ModelServiceBuilder` must:
- be `internal sealed class ModelRunnerBuilder(FluentDockerKernel kernel, string driverId) : IModelRunnerBuilder, IDriverScopedBuilder`
- store `_kernel`, `_driverId`
- expose them via explicit interface implementation `FluentDockerKernel IDriverScopedBuilder.Kernel => _kernel;` / `string IDriverScopedBuilder.DriverId => _driverId;`

Per DESIGN §13.2 the PUBLIC builder interfaces themselves also derive from `IDriverScopedBuilder`:
```csharp
public interface IModelRunnerBuilder : IDriverScopedBuilder { ... }
public interface IModelServiceBuilder : IDriverScopedBuilder { ... }
```
(That is a design choice; existing builders like `IContainerBuilder` do NOT derive from it — only the impl class does. Either works; for model builders the spec makes the public interface derive from it so the `TryDriver`/`RequireDriver` extensions are directly chainable.)

## (2) TryDriver<T> / RequireDriver<T> — exact signatures & impl

File: `/Users/mariotoffia/progs/github/FluentDocker/FluentDocker/Builders/DriverScopedBuilderExtensions.cs:7-28` (entire class)

```csharp
namespace FluentDocker.Builders
{
  public static class DriverScopedBuilderExtensions
  {
    public static T RequireDriver<T>(this IDriverScopedBuilder builder) where T : class
        => builder.Kernel.SysCtl<T>(builder.DriverId);                       // line 16-17

    public static T TryDriver<T>(this IDriverScopedBuilder builder) where T : class
        => builder.Kernel.TrySysCtl<T>(builder.DriverId, out var v) ? v : null; // line 26-27
  }
}
```

- `RequireDriver<T>` → throws `InterfaceNotSupportedException` (via kernel `SysCtl`) when the port is absent; `DriverNotFoundException` when the driver id is unknown.
- `TryDriver<T>` → returns `null` when the port is absent; still throws `DriverNotFoundException` for a missing driver id (because `TrySysCtl` only swallows `InterfaceNotSupportedException`).

**These resolve any interface the pack registered** — so once a model pack registers `typeof(IModelInferenceDriver)`/`IModelManagementDriver`/`IModelRuntimeDriver` in its `_drivers` map, `builder.RequireDriver<IModelInferenceDriver>()` / `builder.TryDriver<IModelManagementDriver>()` just work, no kernel changes.

DESIGN §13.3 dictates the NEW model extension class to mirror this exactly (`/Users/mariotoffia/progs/github/FluentDocker/docs/dmr/DESIGN.md:1340-1345`):
```csharp
public static class ModelDriverScopedBuilderExtensions
{
  public static bool TryUseModelRunner(this IDriverScopedBuilder b, out IModelRunnerBuilder builder);
  public static IModelRunnerBuilder UseModelRunner(this IDriverScopedBuilder b);
  public static IModelServiceBuilder UseModel(this IDriverScopedBuilder b, string reference);
}
```
Implementation intent: `UseModelRunner` calls `b.RequireDriver<IModelInferenceDriver>()` (or management) then constructs `new ModelRunnerBuilder(b.Kernel, b.DriverId)`. `TryUseModelRunner` uses `b.TryDriver<...>()`, returns false + null builder when the pack lacks model support (e.g. Podman without RamaLama). These extensions hang off `IDriverScopedBuilder`, so they are callable on `ContainerBuilder`, `NetworkBuilder`, `VolumeBuilder`, `PodBuilder`, `ModelRunnerBuilder`, etc.

## (5) kernel.SysCtl<T>(driverId) resolution from a pack

File: `/Users/mariotoffia/progs/github/FluentDocker/FluentDocker/Kernel/FluentDockerKernel.cs`

`public class FluentDockerKernel : ISysCtl, IAsyncDisposable, IDisposable` (line 16). Ctor `(IDriverRegistry registry, ILoggerFactory loggerFactory)` (line 31), both required (`ArgumentNullException.ThrowIfNull`). Exposes `public ILoggerFactory LoggerFactory => _loggerFactory;` (line 44) — this is what `ContainerBuilder` uses for `kernel.LoggerFactory.CreateLogger<ContainerBuilder>()` (ContainerBuilder.cs:25).

**Resolution core (lines 57-88):**
```csharp
public object SysCtl(string driverId, Type interfaceType)
{
  ThrowIfDisposed();
  if (_registry.TryGetDriverPack(driverId, out var driverPack))
  {
    if (driverPack.TryResolve(interfaceType, out var resolved))   // 1. pack's IDriverInterfaceResolver
      return resolved;
    return driverPack.SysCtl(driverId, interfaceType);            // 2. pack's type-based ISysCtl (throws InterfaceNotSupportedException)
  }
  if (_registry.TryGetDriver(driverId, out var driver))           // regular driver path
  {
    if (driver is IDriverInterfaceResolver driverResolver &&
        driverResolver.TryResolve(interfaceType, out var driverResolved))
      return driverResolved;                                      // 3.
    if (interfaceType.IsInstanceOfType(driver))
      return driver;                                              // 4. direct cast
    throw new InterfaceNotSupportedException(driverId, interfaceType.Name);
  }
  throw new DriverNotFoundException(driverId);
}
public T SysCtl<T>(string driverId) where T : class => (T)SysCtl(driverId, typeof(T));  // lines 94-97
```
`TrySysCtl<T>` (lines 103-119): calls `SysCtl<T>`, catches `InterfaceNotSupportedException` → returns false; deliberately lets `DriverNotFoundException` propagate ("a missing driver is a hard error, not a 'not supported' case").

So the full chain for `builder.RequireDriver<IModelInferenceDriver>()`:
`RequireDriver` → `kernel.SysCtl<IModelInferenceDriver>(driverId)` → `(IModelInferenceDriver)SysCtl(driverId, typeof(IModelInferenceDriver))` → registry `TryGetDriverPack` → `pack.TryResolve(typeof(IModelInferenceDriver), out resolved)` → returns `_drivers[typeof(IModelInferenceDriver)]`. Port absent → `InterfaceNotSupportedException`; driver id wrong → `DriverNotFoundException`.

**Registry** (`/Users/mariotoffia/progs/github/FluentDocker/FluentDocker/Kernel/DriverRegistry.cs`): `public class DriverRegistry : IDriverRegistry, IDisposable, IAsyncDisposable`. Two `ConcurrentDictionary` maps `_drivers` and `_driverPacks` plus a `SemaphoreSlim _registrationLock`. `RegisterDriverPackAsync` (lines 161-213) under lock: rejects duplicate ids across both maps (`DriverException(..., ErrorCodes.Driver.AlreadyRegistered)`); sets `context.DriverId ??= driverId`; **`context.LoggerFactory = _loggerFactory;`** (line 185 — injects the real factory before init); `await driverPack.InitializeAsync(context, ct)`; `_driverPacks.TryAdd(...)`; `SetDefaultIfFirst(driverId)` (first registered becomes default). `DisposeAsync` disposes packs then drivers (async-or-sync). `GetContext(driverId)` returns the stored context.

`DriverContext` is constructed `new DriverContext(driverId)` everywhere a driver executes (e.g. ContainerBuilder.cs:375 `var context = new DriverContext(_driverId);`). Inside a builder's `ExecuteAsync` you always do: `var driver = _kernel.SysCtl<Drivers.IXxxDriver>(_driverId); var context = new DriverContext(_driverId);` (see InternalBuilders.cs:50-51, 125-126, 236-237; PodBuilder.cs:51-52). A model builder's `BuildAsync` should do the same: `var inf = _kernel.SysCtl<IModelInferenceDriver>(_driverId);` etc.

**KernelBuilder** (`/Users/mariotoffia/progs/github/FluentDocker/FluentDocker/Kernel/KernelBuilder.cs`): `WithDockerCli`/`WithDockerApi`/`WithPodmanCli` (lines 32-59) each create a typed driver builder, `configure(builder)`, add `builder.Build()` (a `DriverConfiguration`). `BuildAsync` (84-106) creates `new FluentDockerKernel(new DriverRegistry(_loggerFactory), _loggerFactory)` then for each config calls `RegisterDriverPackAsync` (if `DriverPack != null`) or `RegisterDriverAsync`, then `SetDefaultDriver` if `IsDefault`. `DockerCliDriverBuilder.Build()` (`DockerCliDriverBuilder.cs:54-73`) returns a `DriverConfiguration { DriverPack = new DockerCliDriverPack(), Context = new DriverContext(_driverId){ Host, CertificatePath, Sudo, SudoPassword, BinaryName, SearchPaths }, IsDefault }`. To wire a model pack into kernel construction, either reuse `DockerCliDriverPack` (it now registers model ports) or add a new pack and surface it via `WithDriver(id, b => b.UseCustomDriverPack(pack))` (`IDriverBuilder.UseCustomDriverPack`, IKernelBuilder.cs:76).

## (7) ContainerBuilder env-injection (WithEnvironment) + the `.Builder()` back-reference

File: `/Users/mariotoffia/progs/github/FluentDocker/FluentDocker/Builders/ContainerBuilder.cs`

**Env storage & injection:** `private readonly Dictionary<string, string> _environment = [];` (line 35). Two `WithEnvironment` overloads:
```csharp
public IContainerBuilder WithEnvironment(string key, string value)   // lines 88-92
{ _environment[key] = value; return this; }

public IContainerBuilder WithEnvironment(string keyValue)            // lines 94-102 — "KEY=VALUE" form
{

  if (parts.Length == 2) _environment[parts[0]] = parts[1];
```

The dictionary is flushed into the driver config in `ExecuteAsync` (lines 407-411): `var config = new Drivers.ContainerCreateConfig { Image = _image, Name = _name, Environment = _environment, PortBindings = _ports, ... };` then `await driver.CreateAsync(context, config, ct)`. So a `WithModel` container extension injects by calling `WithEnvironment(endpointVar, url)` / `WithEnvironment(modelVar, modelRef)` — there is no separate env API; it rides on the existing dictionary.

`IContainerBuilder` env contract is in `/Users/mariotoffia/progs/github/FluentDocker/FluentDocker/Builders/IContainerBuilder.cs:52` (`WithEnvironment(string key, string value)`) and `:59` (`WithEnvironment(string keyValue)`). For host-aliasing the model endpoint on Engine (DESIGN §13.5: `--add-host model-runner.docker.internal:host-gateway`), note there is NO existing `WithAddHost`/extra-hosts builder method — `ContainerBuilder` has networks, networkMode, links, aliases, but no add-host. Adding `WithModel` reachability on Engine would require either a new `WithExtraHost` builder method + a `ContainerCreateConfig` field, or injecting the gateway IP directly into the URL.

**The `.Builder()` back-reference — IMPORTANT GOTCHA:** There is currently **NO `.Builder()` method** on `IContainerBuilder` or `ContainerBuilder`. The existing fluent flow is the lambda form `Builder.UseContainer(c => c.UseImage(...).WithName(...))` (Builder.cs:92) — the configure lambda receives the `IContainerBuilder`, mutates it, and control returns to the outer `Builder` automatically; you never "go back up" from inside the lambda. The DESIGN sample at `/Users/mariotoffia/progs/github/FluentDocker/docs/dmr/DESIGN.md:1396-1404` shows a DIFFERENT (non-lambda) chaining style:
```csharp
new Builder().WithinDriver("docker")
  .UseContainer().UseImage("my-app:latest")
    .WithModel("ai/qwen3")
  .Builder()        // ← back-reference to outer Builder
  .Build();
```
This `.UseContainer()` (no-arg, returning `IContainerBuilder`) and `.Builder()` back-reference **do not exist today** and must be added for that exact spec sample to compile. Two ways to satisfy the design:
- (a) Keep the existing lambda `UseContainer(Action<IContainerBuilder>)` and have `WithModel` be an `IContainerBuilder` extension used INSIDE the lambda (no `.Builder()` needed) — simplest, matches all current code.
- (b) Add a no-arg `IContainerBuilder UseContainer()` overload that registers the operation and returns the `ContainerBuilder`, plus an `IContainerBuilder.Builder()` (or extension) returning the owning `Builder`. This requires `ContainerBuilder` to hold a reference to its owning `Builder` (it currently does NOT — it only holds `_kernel`, `_driverId`).

`WithModel` extension signature per DESIGN §13.5:
```csharp
public static IContainerBuilder WithModel(this IContainerBuilder builder,
    ModelReference model, ModelRunnerEndpoint endpoint = null,
    string endpointVar = "LLM_URL", string modelVar = "LLM_MODEL");
```
Since `IContainerBuilder` itself does NOT derive from `IDriverScopedBuilder`, but its impl `ContainerBuilder` does, a `WithModel` extension that needs the kernel/driverId must cast: `if (builder is IDriverScopedBuilder scoped) { var inf = scoped.TryDriver<IModelInferenceDriver>(); ... }`. That cast is the established way to reach the kernel from inside a public builder interface extension.

## Cross-cutting idioms to copy verbatim
- Builder `ExecuteAsync` returns `Task<IServiceAsync>`; resolves driver via `_kernel.SysCtl<Drivers.IXxxDriver>(_driverId)`; builds a `DriverContext(_driverId)`; calls driver, checks `response.Success`, throws `new DriverException($"...: {response.Error}", response.ErrorCode, response.ErrorContext)` on failure (InternalBuilders.cs:88-94, 136-139; ContainerBuilder.cs:452-455; PodBuilder.cs:63-69), then wraps the result in a `Services.Impl.XxxService(_kernel, _driverId, id, name, removeOnDispose)` and (for pod/container) `await service.StartAsync(ct)`.
- File-size discipline: code ≤ 500 lines, split with `partial class` (ContainerBuilder is `partial`, has a WaitConditions partial — see ContainerBuilder.cs:21 `internal sealed partial class`). DESIGN §3.8 reiterates this for model files.
- `DriverCapabilities.Default()` exists if you need an all-on baseline.
- For a new pack that owns an HTTP connection, mirror `DockerApiDriverPack`: implement `IAsyncDisposable`, keep `IModelApiConnection` as an interface field with `#pragma warning disable CA1859` if tests inject a mock by reflection.
