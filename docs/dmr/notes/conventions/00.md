## 2. CommandResponse<T> — EXACT Ok / Fail signatures (all overloads)

Class is `public class CommandResponse<T>` (NOT sealed, NOT a struct), guarded by `#pragma warning disable CA1000` (static members on generic type — intentional factory pattern). All data props are **init-only** (`get; init;`): `Success`, `Data` (type `T`), `Error`, `ErrorCode`, `ErrorContext ErrorContext`, `int ExitCode`, `string Output`. There is NO public constructor used by callers — always use the factories. Exact factory signatures (CommandResponse.cs:51-102):

```csharp
public static CommandResponse<T> Ok(T data)
public static CommandResponse<T> Ok(T data, string output)
public static CommandResponse<T> Fail(string error, string errorCode = null, int exitCode = -1)
public static CommandResponse<T> Fail(string error, string errorCode, ErrorContext context, int exitCode = -1)
```

Behavior to preserve exactly:
- `Ok(data)` sets `Success=true, Data=data, ExitCode=0`.
- `Ok(data, output)` adds `Output=output`.
- `Fail(error, errorCode=null, exitCode=-1)` sets `ErrorCode = errorCode ?? ErrorCodes.General.Unknown` — the null-coalesce to `ErrorCodes.General.Unknown` ("GEN_000") is the documented default.
- `Fail(error, errorCode, context, exitCode=-1)` sets `ErrorContext = context` (no null-coalesce on errorCode here — caller passes a real code).

`Unit` return convention: methods that "return void" use `CommandResponse<Unit>` and callers do `CommandResponse<Unit>.Ok(Unit.Default)` for success.

## 3. How drivers build ErrorContext + call Fail (the idiom to copy)

Two-tier idiom per operation (from `DockerCliVolumeDriver.cs:57-72`):
```csharp
if (!result.Success)
{
  return CommandResponse<VolumeCreateResult>.Fail(
      result.Error ?? "Volume creation failed",
      ErrorCodes.Volume.CreateFailed,
      CreateErrorContext(context, "CreateVolume", result),  // 4-arg Fail w/ context
      result.ExitCode);
}
// ... on the catch(Exception ex) path use the 2-arg overload (no context):
catch (Exception ex)
{
  return CommandResponse<VolumeCreateResult>.Fail(ex.Message, ErrorCodes.Volume.CreateFailed);
}
```

`CreateErrorContext` is a protected helper on `DockerCliDriverBase` (`DockerCliDriverBase.cs:382-403`), two overloads:
```csharp
protected static ErrorContext CreateErrorContext(DriverContext context, string operation, SimpleCommandResult result)
{
  return new ErrorContext(operation)
  {
    DriverId = context.DriverId,
    Host = context.Host,
    ExitCode = result.ExitCode,
    StdOut = result.Output,
    StdErr = result.Error
  };
}
protected ErrorContext CreateErrorContext(string operation, SimpleCommandResult result) // uses this.Context
  => CreateErrorContext(Context, operation, result);
```
So for a NEW port's CLI driver, derive from the same `DockerCliDriverBase`/`PodmanCliDriverBase` and reuse `CreateErrorContext`. `ErrorContext` itself (ErrorContext.cs) is a plain mutable `public class` with `get; set;` props: `OperationId, DriverId, Host, Operation, int? ExitCode, StdOut, StdErr, Dictionary<string,string> Metadata = []`, `DateTime Timestamp = DateTime.UtcNow`. Ctors: `ErrorContext()` and `ErrorContext(string operation)` (expression body sets `Operation`). It overrides `ToString()` to join non-empty Operation/Driver/Host/ExitCode/OperationId.

## 5. ErrorCodes structure (how to add Model + ModelInference groups)

`public static class ErrorCodes` (namespace `FluentDocker.Model.Drivers`). It contains **nested `public static class` groups**, each holding `public const string` fields. Convention: a per-domain string prefix + zero-padded number. Existing groups and prefixes:
- `General` → `GEN_000..GEN_004` (Unknown="GEN_000", InvalidOperation, InvalidArgument, Timeout, Cancelled)
- `Driver` → `DRV_001..DRV_007` (incl. `CapabilityNotSupported="DRV_007"`, `InterfaceNotSupported="DRV_006"`)
- `Container` → `CNT_001..CNT_023`
- `Image` → `IMG_001..IMG_012`
- `Network` → `NET_001..NET_009`
- `Volume` → `VOL_001..VOL_007`
- `Compose` → `CMP_001..CMP_026`
- `Pod` → `POD_001..POD_011`
- `Kubernetes` → `K8S_001..K8S_003`
- `Machine` → `MACH_001..MACH_009`
- `Manifest` → `MAN_001..MAN_006`
- `Api` → `API_400/401/404/409/500/API_CONN`
- `Config` → `CFG_001..CFG_003`
- `Auth` → `AUTH_001..AUTH_004`
- `Stack` → `STK_001..STK_006` (wrapped in `#pragma warning disable CA1711` / `restore` because the type name ends in "Stack")
- `Service` → `SVC_001..SVC_010`

**To add new groups (mirror exactly):**
```csharp
/// <summary>
/// Model-related error codes (OCI/AI model management)
/// </summary>
public static class Model
{
  public const string NotFound = "MDL_001";
  public const string PullFailed = "MDL_002";
  public const string PushFailed = "MDL_003";
  public const string RemoveFailed = "MDL_004";
  public const string ListFailed = "MDL_005";
  public const string InspectFailed = "MDL_006";
  // ... continue MDL_0NN, zero-padded to 3 digits
}

/// <summary>
/// Model inference error codes
/// </summary>
public static class ModelInference
{
  public const string RunFailed = "MDLINF_001";
  public const string NotSupported = "MDLINF_002";
  // ... MDLINF_0NN
}
```
Pick an unused prefix (`MDL_` / `MDLINF_` are free). Each `const string` gets a `///` doc only optionally (existing groups have a `/// <summary>` on the group but bare consts inside — no per-const docs). The file has NO usings; it's pure nested static classes inside one namespace block. Watch the 500-line code-file limit (file is at 269; adding 2 groups is fine).

public static DriverCapabilities Default()

## 9. JsonHelper — public surface (Common/JsonHelper.cs)

`public static class JsonHelper`, namespace `FluentDocker.Common`. Usings: `System; System.Text.Json; System.Text.Json.Serialization; System.Text.Json.Serialization.Metadata`. Static option singletons (all `{ get; }` thread-safe, built once):
```csharp
public static JsonSerializerOptions DefaultOptions { get; }          // CamelCase, WriteIndented=false, IgnoreNull, AllowReadingFromString, CaseInsensitive=FALSE
public static JsonSerializerOptions CaseInsensitiveOptions { get; }  // same but PropertyNameCaseInsensitive=true
public static JsonSerializerOptions IndentedOptions { get; }         // CamelCase, WriteIndented=true, CaseInsensitive=true
```
All three add `new JsonStringEnumConverter()` and `new TolerantStringConverter()`. **Gotcha:** `TryDeserialize<T>` uses `CaseInsensitiveOptions` (NOT `DefaultOptions`), while `Serialize`/`SerializeToUtf8Bytes` use `DefaultOptions` and `SerializeIndented` uses `IndentedOptions`.

`TryDeserialize` overloads (return `default` on null/whitespace/`JsonException`, never throw):
```csharp
public static T TryDeserialize<T>(string json)
public static T TryDeserialize<T>(string json, JsonTypeInfo<T> typeInfo)   // source-gen
public static T TryDeserialize<T>(ReadOnlySpan<byte> utf8Json)
```
Other helpers:
```csharp
public static string Serialize<T>(T value)
public static byte[] SerializeToUtf8Bytes<T>(T value)
public static string SerializeIndented<T>(T value)
public static JsonElement ParseElement(string json)              // returns RootElement.Clone() (detached, safe to store)
public static string TryGetProperty(string json, string propertyName)        // single-field extract, null on miss/error
public static int? TryGetIntProperty(string json, string propertyName)        // checks ValueKind==Number && TryGetInt32 before reading
```
For NEW-port POCO parsing, follow the codebase rule: use `JsonHelper.TryDeserialize<T>(json)` (STJ) for new code; remember it is case-insensitive + camelCase + tolerant of string-encoded numbers/enums.

## 10. Value-object / POCO conventions to copy verbatim

- **Port interface POCOs** (Config/Result/Filter/entity) are plain `public class` with `get; set;` mutable auto-props — they are NOT sealed and NOT immutable. Mirror this for new-port POCOs.
- **Collection/dictionary props use C# 12 collection-expression initializers `= []`** everywhere: `Dictionary<string,string> Labels { get; set; } = [];`, `List<string> Warnings { get; set; } = [];`. Always initialize collections to `[]` (never leave null).
- **String defaults inline**: e.g. `VolumeCreateConfig.Driver = "local"`, `NetworkCreateConfig.Driver = "bridge"`, `ImageBuildConfig.Rm = true`. Provide sensible literal defaults the same way.
- **Naming**: Config = `XxxCreateConfig`/`XxxBuildConfig`; Result = `XxxCreateResult`/`XxxRemoveResult`/`XxxPruneResult`; Filter = `XxxListFilter`; entity = `Xxx` (e.g. `Volume`, `Network`, `Image`). Prune results expose `List<string> XxxDeleted = []` and (where relevant) `long SpaceReclaimed`.
- **`internal sealed`** is reserved for JSON converters only (e.g. `internal sealed class LabelsConverter : JsonConverter<Dictionary<string,string>>` in `INetworkDriver.cs:267`, applied via `[JsonConverter(typeof(LabelsConverter))]` on the entity's `Labels` prop, lines 259-260). Use this same pattern if your entity labels can arrive as either a CSV string (CLI) or JSON object (API).
- **Async method signature shape** (every port method): `Task<CommandResponse<TPayload>> XxxAsync(DriverContext context, <op-args>, CancellationToken cancellationToken = default);` — `DriverContext context` is ALWAYS first; `CancellationToken cancellationToken = default` is ALWAYS last; optional flags/filters in between get C# defaults (`bool force = false`, `XxxListFilter filter = null`, `string tag = "latest"`). Void ops return `CommandResponse<Unit>`.
- **Progress reporting** (Image pattern, `IImageDriver.cs:27-63`): long-running ops accept `IProgress<XxxProgress> progress = null` placed BEFORE the cancellation token, and define a `public class XxxProgress { get; set; }` POCO. Reuse this for any streaming new-port op (e.g. model pull/inference).
- **`#region` grouping** is used in `IImageDriver.cs` to organize many ops (`#region Pull/Push Operations`, `#region Config Types`, `#region Result Types`, `#region Progress Types`). Mirror for a port with many operations.
- **XML doc comments** (`/// <summary>`, `/// <param>`, `/// <returns>`, `<see cref="CommandResponse{T}"/>`) on every interface method and every public type/member — `GenerateDocumentationFile` is on (CS1591 suppressed but new code is expected to be documented; mirror the dense doc style of `IVolumeDriver.cs`/`INetworkDriver.cs`).
- **File-size rule** (CLAUDE.md): code files max 500 lines. `IImageDriver.cs` is 451 — if a new port grows large, split POCOs into `FluentDocker/Model/Xxx/*.cs` (separate files under `namespace FluentDocker.Model.Xxx`) and keep only the interface + small inline types in `IXxxDriver.cs`, or use `partial`/multiple files. There is no existing `IImageDriver.Operations.cs`; the prompt's "(and .Operations if present)" — it is NOT present.
