### Core mechanics (`MockDriverPack.cs`)
- Private state: `private readonly Dictionary<Type, object> _drivers = [];`, `_initialized`, `_capabilities`, `_isHealthy`.
- Aliases at top (lines 12-17) — REQUIRED because `CommandResponse<T>` exists in both `Model.Containers` and `Model.Drivers`:
  ```csharp
  using DriverCapabilities = FluentDocker.Model.Drivers.DriverCapabilities;
  using DriverContext = FluentDocker.Model.Drivers.DriverContext;
  using DriverResponse = FluentDocker.Model.Drivers.CommandResponse<FluentDocker.Model.Drivers.Unit>;
  using DriverType = FluentDocker.Model.Drivers.DriverType;
  using RuntimeType = FluentDocker.Model.Drivers.RuntimeType;
  using Unit = FluentDocker.Model.Drivers.Unit;
  ```
- Mock driver props are `public Mock<IXxxDriver> XxxDriver { get; } = new Mock<IXxxDriver>();` (lines 35-60).
- `Type => DriverType.DockerCli;` `Runtime => RuntimeType.Docker;`
- Ctor calls `_capabilities = DriverCapabilities.Default(); SetupDefaultBehaviors();`.
- **`InitializeAsync`** (lines 96-107) populates `_drivers[typeof(IXxxDriver)] = XxxDriver.Object;` for the always-on drivers, sets `_initialized = true`, returns `Task.CompletedTask`. The Swarm/PodmanKube mocks are NOT registered here — they are opt-in via `Enable*Driver()` which adds to `_drivers` (this is why those `Enable*` helpers exist and must be called BEFORE `InitializeAsync`/resolution).
- **`SysCtl<T>(string driverId)`** (lines 122-135): throws `InvalidOperationException("MockDriverPack not initialized...")` if `!_initialized`; looks up `_drivers[typeof(T)]`; else `throw new InterfaceNotSupportedException(driverId, requestedType.Name);`.
- `TryResolve(Type, out object)`, `GetSupportedInterfaces()`, `SysCtl(string, Type)`, `TrySysCtl<T>(string, out T)` all guard `_initialized` and read `_drivers`.
- **`RegisterCustomDriver<T>(T impl)`** (lines 191-194): `_drivers[typeof(T)] = implementation;` — escape hatch to inject arbitrary interfaces.
- `SetupDefaultBehaviors()` (lines 201-207) pre-wires `SystemDriver.PingAsync(...).ReturnsAsync(CommandResponse<Unit>.Ok(Unit.Default))`.

### Setup* helper idiom (return `this` for chaining)
```csharp
public MockDriverPack SetupContainerInspect(string containerId = "test-container-123", bool running = true)
```

### HOW TO ADD MODEL PORTS (DMR M1) — new file `MockDriverPack.Model.cs`
The DMR interfaces (from `docs/dmr/TASKS.md` P1-P5): `IModelManagementDriver`, `IModelRuntimeDriver`, `IModelInferenceDriver` (incl. `IAsyncEnumerable` streaming sigs), optional aggregate `IModelDriver`, and `IModelApiConnection`. Mirror the Swarm/PodmanKube opt-in pattern exactly:
```csharp
public partial class MockDriverPack
{
  public Mock<IModelManagementDriver> ModelManagementDriver { get; } = new Mock<IModelManagementDriver>();
  public Mock<IModelRuntimeDriver> ModelRuntimeDriver { get; } = new Mock<IModelRuntimeDriver>();
  public Mock<IModelInferenceDriver> ModelInferenceDriver { get; } = new Mock<IModelInferenceDriver>();

  public MockDriverPack EnableModelDrivers()
  {
    _drivers[typeof(IModelManagementDriver)] = ModelManagementDriver.Object;
    _drivers[typeof(IModelRuntimeDriver)]    = ModelRuntimeDriver.Object;
    _drivers[typeof(IModelInferenceDriver)]  = ModelInferenceDriver.Object;
    return this;
  }

  public MockDriverPack SetupModelList(params ModelInfo[] models)
  {
    ModelManagementDriver
        .Setup(d => d.ListAsync(It.IsAny<DriverContext>(), It.IsAny<CancellationToken>()))
        .ReturnsAsync(CommandResponse<IList<ModelInfo>>.Ok([.. models]));
    return this;
  }
  // SetupModelInspect / SetupModelPull / SetupModelLoad / SetupModelChat ... same shape.
}
```
For `IAsyncEnumerable<T>` streaming setups (inference), the mock must return an async stream, e.g. with a local async iterator helper and `.Returns(AsyncEnum(...))` rather than `.ReturnsAsync(...)`. `_drivers` is `private` but accessible to all partials of the same class (same compilation unit type) — this is the mechanism the Swarm/PodmanKube partials rely on. **CRITICAL: model drivers are opt-in — call `EnableModelDrivers()` BEFORE `InitializeAsync`/resolution, OR add them in `InitializeAsync` if you want always-on (Swarm/Kube chose opt-in to keep base pack lean).** Since `InitializeAsync` already ran in `CreateWithMockDriverAsync`, prefer adding model drivers inside `InitializeAsync` OR enable+register before kernel build; simplest is to register in `_drivers` at `Enable*` time and ensure `Enable*` is called before kernel registration (the `CreateWithMockDriverAsync(driverId, mockPack)` overload calls `InitializeAsync` itself, so enable on the pack first, then pass it in — but note enable mutates `_drivers` which is only read after `_initialized`; since `Enable*` writes directly to `_drivers` it works pre- or post-Initialize).

## (3) MockDockerApiConnection — structure to mirror for `MockModelApiConnection`

`FluentDocker.Tests/CoreTests/Driver/DockerApi/MockDockerApiConnection.cs` — hand-rolled (NO Moq), `public sealed class MockDockerApiConnection : IDockerApiConnection`.

The connection interface to model on (`FluentDocker/Drivers/Docker/Api/Connection/IDockerApiConnection.cs`): `IAsyncDisposable` with `GetAsync/PostAsync/PutAsync/DeleteAsync` → `Task<HttpResponseMessage>`, `GetStreamAsync/PostStreamAsync` → `Task<Stream>`, `Task<bool> PingAsync`, `string ApiVersion { get; }`. (`IModelApiConnection` is DMR task P5 — design it the same shape; the SSE streams come back through a `Task<Stream>` method.)

### Key constructs to copy
- **Captured request record** (top-level in file, line 17): `public sealed record CapturedRequest(string Method, string Path, string Body);`
- **Internal canned-response struct** (lines 25-31):
  ```csharp
  private readonly record struct ResponseEntry(
      string Method, string PathContains, HttpStatusCode StatusCode,
      string JsonBody, string StreamContent, byte[] StreamBytes);
  ```
- State: `private readonly List<ResponseEntry> _entries = [];`, `private readonly List<CapturedRequest> _requests = [];`, `private bool _pingSuccess = true;`. `public string ApiVersion { get; set; } = "1.45";`
- **Fluent Setup methods** all return `this` (lines 41-97):
  ```csharp
  public MockDockerApiConnection SetupGet(string pathContains, int statusCode, string jsonBody) {
    _entries.Add(new ResponseEntry("GET", pathContains, (HttpStatusCode)statusCode, jsonBody, null, null));
    return this; }
  // SetupPost / SetupPut / SetupDelete identical with method name.
  public MockDockerApiConnection SetupStream(string pathContains, string streamContent) {
    _entries.Add(new ResponseEntry("STREAM", pathContains, HttpStatusCode.OK, null, streamContent, null));
    return this; }
  public MockDockerApiConnection SetupStreamBytes(string pathContains, byte[] bytes) {  // RAW BINARY — for SSE/multiplexed frames
    _entries.Add(new ResponseEntry("STREAM", pathContains, HttpStatusCode.OK, null, null, bytes));
    return this; }
  public MockDockerApiConnection SetupPing(bool success) { _pingSuccess = success; return this; }
  ```
- **Verification**: `public IReadOnlyList<CapturedRequest> GetRequests() => _requests;`
- **Interface impl** records then resolves:
  ```csharp
  public Task<HttpResponseMessage> GetAsync(string path, CancellationToken ct = default) {
    Record("GET", path, null); return Task.FromResult(Resolve("GET", path)); }
  public async Task<HttpResponseMessage> PostAsync(string path, HttpContent? content = null, CancellationToken ct = default) {
    var body = content is not null ? await content.ReadAsStringAsync(ct) : null;  // captures body for assertions
    Record("POST", path, body); return Resolve("POST", path); }
  public Task<Stream> GetStreamAsync(string path, CancellationToken ct = default) {
    Record("GET_STREAM", path, null); return Task.FromResult(ResolveStream(path)); }
  public Task<Stream> PostStreamAsync(string path, HttpContent? content = null, CancellationToken ct = default) {
    Record("POST_STREAM", path, null); return Task.FromResult(ResolveStream(path)); }
  public Task<bool> PingAsync(CancellationToken ct = default) { Record("PING", "/_ping", null); return Task.FromResult(_pingSuccess); }
  public ValueTask DisposeAsync() => ValueTask.CompletedTask;
  ```
- **Internals**:
  - `Record(method, path, body)` → `_requests.Add(new CapturedRequest(...))`.
  - `Resolve(method, path)` (lines 171-192): `_entries.Where(e => e.Method == method && path.Contains(e.PathContains)).LastOrDefault()` (LAST match wins → later Setup overrides earlier). On no match returns `HttpStatusCode.NotFound` with JSON `{"message":"no mock for METHOD PATH"}`. On match returns `new HttpResponseMessage(entry.StatusCode){ Content = new StringContent(entry.JsonBody ?? "{}", Encoding.UTF8, "application/json") }`.
  - `ResolveStream(path)` (lines 194-207, with `#pragma warning disable CA1859`): matches `Method == "STREAM"`; if `entry.StreamBytes != null` returns `new MemoryStream(entry.StreamBytes)`; else `new MemoryStream(Encoding.UTF8.GetBytes(text))`.

### MockModelApiConnection additions for SSE (DMR M2: "no Moq, programmable JSON + SSE script + forced fault")
- **SSE is a byte/text stream returned via the stream method**; reuse `SetupStreamBytes`/`SetupStream`. SSE wire format = lines `data: {json}\n\n`, terminated by `data: [DONE]\n\n`. Build the script as a string and feed via `SetupStream("/chat/completions", sseScript)` or as bytes for exact-encoding tests.
- **Forced fault / mid-stream fault**: add either a `SetupFault(pathContains, HttpStatusCode, jsonBody)` that registers an error entry, OR a `SetupStreamFault` that returns a stream that throws partway (wrap `MemoryStream` in a custom `Stream` whose `Read` throws after N bytes) — needed for A3 "malformed→StreamParseError, cancel mid-stream".
- Keep `record CapturedRequest` + `GetRequests()` for command/path assertions identical.

## (4) EXACT integration-gating idiom — `$XunitDynamicSkip$`

There is **no custom Skip attribute, no `Assert.Skip`, no `[CollectionDefinition]`**. Gating is done two ways:

1. **Trait + Collection on the class** (categorization + serialization, NOT skipping):
   ```csharp
   [Trait("Category", "Integration")]
   [Collection("DockerDriver")]
   public partial class ContainerDriverTests : DockerDriverTestBase
   ```
   (`FluentDocker.Tests/Integration/DockerCliDriver/ContainerDriverTests.cs:13-16`). The DockerApi base uses `[Collection("DockerDriver")]` on the base class (`DockerApiDriverTestBase.cs:15`) and `[Trait("Category", "Integration")]` on the concrete (`DockerApiDriverTests.cs:13`). `"DockerDriver"` is a plain string collection — no `CollectionDefinition` class exists; it just serializes those tests so they don't fight over the daemon. Integration test selection at the CLI is via trait filter, e.g. `--filter-trait "Category=Integration"` / the Makefile target.

2. **Runtime dynamic skip** — the EXACT idiom for "skip when Docker/DMR/image absent". Throw an `InvalidOperationException` whose message is prefixed with the magic sentinel `"$XunitDynamicSkip$"`; xUnit v3 turns that into a SKIPPED (not failed) result:
   ```csharp
   if (!pullResult.Success)
     throw new InvalidOperationException("$XunitDynamicSkip$" +
         "Image pull failed (network/rate-limit): " + pullResult.Error);
   ```
   (`FluentDocker.Tests/Integration/DockerApiDriver/DockerApiDriverTests.cs:199-202`.) Also used inline with `?? throw`:
   ```csharp
   var img = list.Data.FirstOrDefault(i => i.RepoTags?.Any(t => t.Contains("alpine")) == true)
       ?? throw new InvalidOperationException("$XunitDynamicSkip$Alpine image not found");
   ```
   (`DockerApiDriverTests.Image.cs:27`).

**For DMR (TASKS.md I1/I2):** "DMR-availability-gated … skips cleanly when absent". Mirror this — in the model integration test base, probe `docker model status` (or the model runtime driver's `StatusAsync`) in `InitializeAsync`/at top of each `[Fact]`, and on failure `throw new InvalidOperationException("$XunitDynamicSkip$DMR not available");`. CI mirrors the Docker gating probe (task I2). `[Trait("Category", "Integration")]`; PR runs ubuntu-only.

`DockerApiDriverTestBase.cs` / `DockerDriverTestBase.cs`:

## (5) xUnit v3 + Moq idioms used here

- **Facts**: `[Fact] public async Task Method_Scenario_Expected()`. Class-level `[Trait("Category", "Unit")]` (e.g. `ContainerServiceTests.Operations.cs:17`) and sometimes ALSO method-level `[Trait("Category", "Unit")]` (lines 22-23).
- **CancellationToken**: xUnit v3 provides `TestContext.Current.CancellationToken` — pass it to every awaited driver call: `await service.InspectAsync(cancellationToken: TestContext.Current.CancellationToken)`. This is pervasive and expected in every async test.
- **Asserts** (xUnit, NOT FluentAssertions): `Assert.True(result.Success, $"... {result.Error}")` (always with a message that surfaces `.Error`), `Assert.NotNull`, `Assert.Equal(expected, actual)`, `Assert.Single(collection)`, `Assert.Contains(item, collection)` / `Assert.Contains("substr", str)`, `Assert.False(string.IsNullOrEmpty(x), "msg")`.
- **Moq verify**: `mockPack.ContainerDriver.Verify(d => d.InspectAsync(It.IsAny<DriverContext>(), It.Is<string>(s => s == "test-container-123"), It.IsAny<CancellationToken>()), Times.Once);` (`ContainerServiceTests.Operations.cs:43-46`). Fully-qualify ambiguous types in-line: `It.IsAny<FluentDocker.Model.Drivers.DriverContext>()`, `It.IsAny<System.Threading.CancellationToken>()`.
- **Unit test lifecycle** (no fixture base): construct `MockDriverPack`, call `Setup*`, build kernel via `MockKernelBuilderExtensions.CreateWithMockDriverAsync("docker", mockPack)`, instantiate the SUT service, run in `try { ... } finally { kernel.Dispose(); }`. Example `ContainerServiceTests.Operations.cs:25-52`.
- **MockDockerApiConnection unit-driver test idiom** (`DockerApiImageDriverTests.cs:16-21,28-50`):

## Quick gotchas / cross-references
- `CommandResponse<T>` ambiguity (Model.Containers vs Model.Drivers) — alias one (`MockDriverPack.cs:14`) or fully qualify `FluentDocker.Model.Drivers.CommandResponse<...>` (used verbatim in `MockDriverPack.cs`).
- Swarm/PodmanKube mocks are OPT-IN via `Enable*Driver()`; base pack only auto-registers container/image/network/volume/compose/system (`InitializeAsync` lines 98-103). Add model ports the same way.
- xUnit v3 `IAsyncLifetime` → `ValueTask` returns (NOT `Task`); `TestContext.Current.CancellationToken` is the v3 ambient token.
- Fixture copy is `Condition="'$(Configuration)' == 'Debug'"` only — embedded resources (recommended for DMR) avoid this Debug-only fragility and survive Release test runs.
- Resolve picks `LastOrDefault` match → register specific overrides AFTER generic ones in `MockModelApiConnection`.
